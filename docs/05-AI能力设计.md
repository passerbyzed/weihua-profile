# 05 AI 能力设计

> 所属：卫华产品质量智能平台（Demo）设计文档 ｜ 版本 v0.1 ｜ 2026-11-10
> 本文说明三项 AI 能力怎么算、怎么输出、怎么保证不胡说。

## 一、能力总览

| 能力 | 归属 | 输入 | 输出 | AI / 规则分工 | 目标耗时 |
|---|---|---|---|---|---|
| C1 问题要素抽取 | M1 | 报修单文本、现象描述 | 结构化问题卡（客户/整机/部件/现象/时间） | AI 抽取 + 词典归一 + 规则校验 | ≤ 3 s |
| C2 相似问题召回 | M1 | 结构化问题卡 | 历史问题列表 + 命中原因 + 相似度 | 结构化过滤 + 向量 + 加权排序 | ≤ 1 s |
| C3 质量链补全 | M1 | 问题 + 整机档案 | 七段证据链 + 断点 | 规则取数 + AI 归纳 | ≤ 3 s |
| C4 根因假设与处置建议 | M1 | 问题 + 历史 + 档案 | 假设列表 + 建议措施 + 证据 | 规则候选 + AI 排序与表述 | ≤ 3 s |
| C5 协议问答 | M2 | 选中协议 + 问题 | 逐字原文 + 页码 + 引用 | 检索 + 原文拼接（不使用模型生成） | ≤ 5 s |
| C6 不符合项判定 | M2 | 检查项 + 实测值 | 三方对照 + 判定 + 差异说明 | 规则比对为主，AI 解释为辅 | ≤ 5 s |
| C7 规则计算 | M3 | 规则 + 问题集 | 窗口内匹配数、涉及整机/客户 | 纯规则 | ≤ 1 s |
| C8 高频预警 | M3 | 统计结果 + 规则 | 预警 + 证据 + 可能原因 + 建议 | 规则触发 + AI 解释 | 每日/实时 |
| C9 报告生成 | M3 | 周期数据 | 分析报告初稿 | AI 生成 + 模板约束 | ≤ 30 s |

**总原则**：能用规则算的不用模型算（数字、阈值、比对），模型只负责「理解语言」和「组织表达」，并且输出必须是结构化 JSON + 证据。

## 二、通用设计

### 2.1 五条硬约束

1. **结构化输出**：所有能力输出 JSON Schema 校验，校验失败重试一次，仍失败降级为模板输出。
2. **证据绑定**：结论中的每个事实性断言必须挂 `evidence`（问题 ID / 条款 ID / 单据号）。
3. **可重算**：保存 `prompt_version`、`model`、`input_json`，换模型可重跑，不覆盖人工确认版。
4. **不确定表达**：低置信用「可能 / 建议核实」，禁止用肯定语气陈述推测。
5. **人可推翻**：所有 AI 结论都有「确认 / 修正 / 有异议」，修正结果反哺评测集。

### 2.2 Prompt 分层

```
┌ 系统层：角色、边界、输出格式、禁止事项（稳定，改动需版本号）
├ 任务层：本次任务说明 + 输出 Schema
├ 上下文层：问题卡 / 检索到的历史 / 检索到的条款（动态）
└ 示例层：1～2 个 few-shot（可选，用于稳定格式）
```

### 2.3 模型与参数

| 用途 | 建议 | 说明 |
|---|---|---|
| 抽取 / 归纳 / 问答 | DeepSeek `deepseek-chat`（与售后项目一致） | 温度 0.1～0.3，开启 JSON 输出 |
| 向量 | 本地 `bge-small-zh-v1.5` 或云端 embedding | Demo 数据量小，本地优先，避免网络依赖 |
| 重排 | 规则 + LLM 二选一 | Demo 可先不做重排 |
| 大模型兜底 | 无 Key 时使用规则模板 | 保证 Demo 可离线运行 |

## 三、C1～C4：售后问题研判（M1）

### 3.1 C1 要素抽取

**输入**：报修单原文（问题描述、部件、客户、产品编号），可能包含语音转写文本。
**输出 Schema**：

```json
{
  "machine_no": {"value": "LD5-2024-0316", "confidence": 0.98, "source_span": "产品编号：LD5-2024-0316"},
  "customer": {"value": "河南华丰食品有限公司", "confidence": 0.95},
  "component_raw": {"value": "卷筒轴承座", "confidence": 0.9},
  "fault_mode": {"value": "异响", "confidence": 0.92},
  "phenomenon": {"value": "起升时左侧异响，重载时明显", "confidence": 0.9},
  "discovered_at": {"value": "2026-11-08", "confidence": 0.99},
  "stage": {"value": "使用", "confidence": 0.95},
  "severity": {"value": "一般", "confidence": 0.7},
  "missing_fields": []
}
```

处理顺序：

1. 规则/正则先抓产品编号（格式固定，准确率最高）。
2. 词典匹配部件别名（吊钩/钩头/吊钩组）。
3. 模型抽取现象、时间、严重程度。
4. 交叉校验：发现时间不得早于出厂日期；部件必须能在词典中找到，否则标 `待归一`。

### 3.2 C2 四轴相似召回

**四轴**：

| 轴 | 判定 | 说明 |
|---|---|---|
| 同客户 | `customer_id` 相同（含集团归并） | 同客户往往同工况、同使用习惯 |
| 同机型 | `model_id` 相同 + 规格相近（起重量/跨度/工作级别差 ≤ 1 档） | 设计同源 |
| 同部件 | `component_id` 相同；或同中类 | 部件归一后比较 |
| 同现象 | `fault_mode` 相同，或现象向量相似度 ≥ 0.75 | 语义 |

**打分公式**：

```
score = 0.30 × semantic_sim
      + 0.25 × component_match      // 1.0 同部件 / 0.6 同中类 / 0
      + 0.20 × model_match          // 1.0 同机型 / 0.5 同系列 / 0
      + 0.10 × customer_match       // 1.0 同客户 / 0.5 同集团 / 0
      + 0.10 × time_decay           // exp(-月数/18)
      + 0.05 × fault_mode_match     // 1.0 同现象 / 0.5 同大类
```

**分档**（用于界面标注）：

| 档 | 条件 | 展示 |
|---|---|---|
| A 高度相似 | 四轴全中 或 score ≥ 0.85 | 置顶，「高度相似」红色标签 |
| B 较相似 | 三轴命中 或 score ≥ 0.70 | 正常展示 |
| C 可参考 | 两轴命中 或 score ≥ 0.55 | 折叠区 |
| D 弱相关 | 其余 | 不展示（除非用户展开「查看更多」） |

**每条结果必须回传命中原因**：`["同客户","同部件","现象相似 92%"]` —— 让人知道「为什么给我看这条」。

### 3.3 C3 质量链补全

七段定义与取数来源：

| 段 | 内容 | 取数 | 断点判定 |
|---|---|---|---|
| 1 需求/合同 | 该整机的非标要求摘要 | 合同 + 技术协议 + 变更单 | 无档案 |
| 2 设计 | 图号、版本、设计人、变更 | 图纸元数据 + 变更单 | 无图纸或版本缺失 |
| 3 来料 | 供应商、炉批号、材质证明 | 追溯记录 + 检验记录 | 无批次 |
| 4 制造 | 班组、工序、工艺参数 | 追溯记录 | 无班组/工序 |
| 5 检验 | 检验项、实测值、判定 | 检验记录 | 无检验记录 ← 最常见断点 |
| 6 交付 | 出厂日期、安装、验收 | 整机 + 验收记录 | 无验收 |
| 7 售后 | 本次问题、历史问题、处置 | 质量问题表 | — |

**输出**：

```json
{
  "chain": [
    {"stage": "需求/合同", "status": "ok", "summary": "协议要求面漆240μm、吊钩35CrMo、上翼缘25mm", "refs": ["DOC-TA-...", "DOC-ECN-..."]},
    {"stage": "设计", "status": "ok", "summary": "总图 QD-2024-0316-01 v2，设计人 李某", "refs": ["DOC-DWG-..."]},
    {"stage": "检验", "status": "missing", "summary": "未找到该批次起升机构装配检验记录", "refs": []}
  ],
  "completeness": 5,
  "total": 7,
  "gaps": ["检验段缺失：无装配检验记录，无法判断同轴度是否检验过"]
}
```

**完整度评分**：`filled / 7`，四舍五入到整数；低于 5 的在问题详情页顶部提示「追溯不完整」。

### 3.4 C4 根因假设与处置建议

**候选生成（规则）**：用「部件 × 现象 → 常见根因」矩阵生成 2～4 个候选。示例：

| 部件 | 现象 | 常见根因候选 |
|---|---|---|
| 卷筒轴承座 | 异响 | 同轴度超差、轴承损坏、润滑不足、安装螺栓松动 |
| 车轮 | 啃轨 | 轨距超差、车轮同位差、轨道安装偏差、车轮材质 |
| 涂装层 | 起泡/脱落 | 前处理未达 Sa2.5、除锈后待涂超时、环境湿度高、漆膜过厚 |
| 电控柜 | 跳闸 | 绝缘不良、元件选型偏小、进水受潮、接线错误 |

**AI 的活**：结合历史处置结果、检验记录、档案要求，对候选排序、补充描述、给出验证方法（如「复测同轴度」），并标注证据。

**处置建议排序**：

```
建议分 = 0.4 × 历史解决率
       + 0.3 × 相似度（采用该措施的历史问题与本次的相似度）
       + 0.2 × 采用频次归一
       + 0.1 × 成本/耗时（越低越高）
```

每条建议显示：`采用 3 次 · 解决 2 次 · 平均闭环 6 天 · 来源 QI-2024-0912`。

**约束**：建议只来自历史真实措施或标准工艺库，不允许模型臆造「更换整机」这类不存在的手段。

### 3.5 M1 研判输出 Schema（汇总）

```json
{
  "issue_id": 32,
  "extraction": { "...": "见 3.1" },
  "similar_issues": [
    {"issue_id": 12, "issue_no": "QI-202409-0012", "score": 0.92, "reasons": ["同客户","同部件","现象相似92%"], "handling": "更换轴承座并复测同轴度", "cause": "制作问题 / 同轴度超差", "resolved": true}
  ],
  "quality_chain": { "...": "见 3.3" },
  "hypotheses": [
    {"cause": "卷筒轴承座同轴度超差", "confidence": "medium", "evidence": ["QI-202409-0012", "TRACE-...", "INSP-...-missing"], "verify": "复测轴承座同轴度，标准 ≤0.1mm"}
  ],
  "suggestions": [
    {"measure": "更换轴承座并复测同轴度", "score": 0.86, "history": "采用3次/解决2次/平均6天", "evidence": ["QI-202409-0012"]}
  ],
  "gaps": ["无装配检验记录"],
  "confidence": "medium"
}
```

## 四、C5～C6：协议问答与不符合项核对（M2）

> 检索与引用细节见 [04 技术协议库与引用溯源设计](04-档案知识库与引用溯源设计.md)，此处只写 AI 侧。
### 4.1 C5 问答流程（7 步）

| 步 | 动作 | 失败处理 |
|---|---|---|
| 1 | 选中协议 + 对象识别：油漆、吊钩、钢板、质保、钢丝绳…（可多个） | 识别不出时提示指明对象 |
| 2 | 条款召回：按对象匹配协议中的 values/components | 无命中 → 「协议未提及」 |
| 3 | 页码定位：条款号 + PDF 页码 + 原文 | 条款缺失 → 跳过该对象 |
| 4 | 结构化组装：逐项要求 + 引用编号 | — |
| 5 | 冲突/缺口：同一对象多条款不一致时并列 | 无冲突则为空 |
| 6 | 原文拼接：按条款顺序返回逐字原文，不生成结论 | — |
| 7 | 自检：数字与文字必须逐字来自条款原文 | 不通过 → 不返回该条 |

### 4.2 C6 不符合项判定（规则优先）

判定不交给模型，用确定性规则：

```
输入：检查项 item_code、实测值 measured
1. 取技术协议中该项的原文要求与条款（如箱梁内部漆膜总厚度 ≥150μm）
2. 比对：measured vs requirement（含单位）
3. 判定：
   - 实测 ≥ 要求 → 符合协议要求
   - 实测 < 要求 → 不符合协议要求
   - 协议未规定 → 无法判定，提示补充依据
4. 输出：要求值、实测值、判定、条款号、页码、协议原文
5. 建议动作由规则生成（返工/让步接收/同批核查）
```

**为什么不让模型判合格**：质量判定必须可解释、可复现、可审计；规则算得出来的，不引入概率。

### 4.3 问答自检（grounding）

对答案中每条 item：

1. 收集其 `citations`。
2. 从引用条款原文中提取数字与关键词。
3. 检查答案里的数字（150μm、8mm、9、Q345B、12 个月）是否逐字出现在引用原文。
4. 检查结论方向（「协议要求」）是否与条款语义一致。
5. 不通过 → 该条标 `unsupported`，从结论中移除，放入「待核实」。

## 五、C7～C9：规则预警（M3）

### 5.1 规则结构

一条预警规则 = **故障类型 + 原因归属 + 厂家 + 问题部件 + 备注关键词 + 时间窗口 + 次数阈值 + 等级**。

| 条件 | 取值 | 空值含义 |
|---|---|---|
| 故障类型 | 其他类 / 机械类 / 电气类 | 不限 |
| 原因归属 | 制作 / 发货 / 外协 / 客户（质保内）/ 客户（质保外）/ 设计 / 技术支持 / 公司自营 / 其他 | 不限 |
| 厂家 | 供应商/外协厂（含「自制」） | 不限 |
| 问题部件 | 自由输入，按包含匹配 | 不限 |
| 备注 | 关键词，空格/顿号分隔 | 不限 |
| 时间窗口 | 1～730 天 | — |
| 次数阈值 | 1～50 | — |
| 等级 | 红 / 橙 / 黄 / 提示 | — |

示例：`其他类 + 制作问题 + 部件含「涂装层」+ 120 天 + ≥3 次 + 橙` → 「涂装制作问题聚集」。

### 5.2 匹配算法

```
for rule in 启用的规则:
    start = 今天 - rule.window_days
    evidence = [issue for issue in 问题库
                if issue.date >= start
                and (rule.fault_type 为空 or issue.fault_type == rule.fault_type)
                and (rule.attribution 为空 or issue.attribution_raw == rule.attribution)
                and (rule.manufacturer 为空 or issue.supplier == rule.manufacturer)
                and (rule.component 为空 or rule.component in issue.component)
                and (rule.remark 为空 or 任一关键词命中 现象/描述/根因/处置)]
    if len(evidence) >= rule.threshold:
        生成一条预警（证据 = evidence）
```

约束：

- 条件之间是 **AND**，空值表示不限。
- 部件是**包含匹配**（填「涂装」可命中「涂装层」），其余是精确匹配。
- 备注是**隐式条件**：拆词后任一关键词命中问题文本即算；界面必须明确提示，避免误用。
- 窗口是滚动窗口，含今天；阈值口径是**问题次数**，不是整机台数。
- 一条规则只出一条预警；多个班组/设计人/整机作为证据分布展示，不再按对象拆条。
- 同一规则同一时间只保留一条预警，新证据追加。

### 5.3 预警卡片字段

| 字段 | 来源 |
|---|---|
| 规则名 / 规则号 | 规则配置 |
| 条件摘要 | 由规则条件拼成（如「故障类型=其他类，原因归属=制作问题，部件含『涂装层』」） |
| 问题数 / 阈值 / 窗口 | 计算 |
| 涉及整机 / 客户 | 证据去重计数 |
| 班组 / 设计 / 厂家分布 | 证据中非空字段去重 |
| 证据问题 | 按报修日期倒序 |
| 可能原因 | 按（原因归属 × 部件）查处置库，规则生成 |
| AI 建议 | 点击「生成 AI 建议」由 DeepSeek 生成，按预警证据给出 3～4 条可执行建议；未配置 Key 时显示规则建议 |
| 人工备注 | 手动输入并保存，随预警留痕 |

### 5.4 预警文案生成

可能原因和建议动作来自「原因归属 × 部件」的处置库（`ALERT_PLAYBOOK`），例如：

| 原因归属 | 部件 | 可能原因 | 建议动作 |
|---|---|---|---|
| 制作问题 | 涂装层 | 前处理、待涂时间、雨季湿度控制不稳定 | 核查前处理与待涂记录，雨季除湿，补漆按色板与遍数 |
| 制作问题 | 卷筒轴承座 | 同轴度与装配找正不到位 | 复测同轴度，补齐装配检验记录 |
| 外协问题 | 起升电机 | 绝缘/防护等级不满足，来料检验未覆盖 | 约谈供应商，加严绝缘与防护复验 |
| 设计问题 | 车轮 | 轨距/同位差公差标注超出工艺能力 | 复核图纸公差，整改后强制版本校验 |
| 发货问题 | 涂装层 | 包装固定与运输防护不足 | 复核包装方案，增加护角与固定点 |

没有匹配项时用兜底文案，不调用大模型，保证预警口径稳定、可复现。

### 5.5 配置与边界

| 约束 | 做法 |
|---|---|
| 可配置 | 页面改条件/窗口/阈值/等级，保存后立即重算 |
| 可解释 | 卡片展示完整条件、阈值、窗口和全部证据 |
| 去重 | 以规则 ID 为键，一条规则一条预警 |
| 误报 | 支持「误报」关闭，状态留痕，规则可继续调整 |
| 口径 | 阈值按问题次数，不按整机台数；涉及整机数单独展示 |
| 备注 | 作为关键词隐式条件，界面明确提示 |
| 对象 | 不针对具体人，避免把预警变成个人考核工具 |

## 六、Prompt 设计

### 6.1 系统提示词骨架（研判）

```
你是起重机售后质量分析助手。你的任务是基于给定的「问题卡」「历史相似问题」「质量链数据」，
输出结构化的研判结果。

硬性要求：
1. 只能使用输入中提供的历史问题和证据，不得编造历史、数字、单据号。
2. 每个根因假设必须列出 evidence（历史问题编号或档案条款号）；找不到证据就不要给该假设。
3. 不确定时用「可能」「建议核实」，confidence 标 medium/low。
4. 只输出 JSON，符合给定 Schema，不要输出解释性文字。
5. 历史问题为空时，similar_issues 返回空数组，不要虚构。
```

### 6.2 任务提示词骨架（问答）

```
任务：回答用户关于技术协议文件《{{doc_title}}》的问题。

用户问题：{{question}}
文件：{{doc_title}} {{version}}（{{pages}} 页）

检索到的条款（仅可使用这些）：
{{#each clauses}}
[{{clause_no}}] {{section_path}}｜第{{page}}页
原文：{{text}}
{{/each}}

输出要求：
- 逐项回答用户问到的每个对象（如油漆、吊钩、钢板），每项给 verdict / requirement / citations。
- verdict 取值：specified | not_mentioned。
- citations 只能使用上面列出的条款编号；没有依据的项写 not_mentioned 并在 gaps 说明。
- 数字必须逐字来自条款原文，不得改写或推算。
- 不要复述整段原文，只摘关键句。
```

### 6.3 few-shot 的作用

只用于稳定格式，不用于「教知识」。示例从真实标注数据中取，且必须与当前整机无关，避免模型照抄。

## 七、置信度与人工复核

### 7.1 置信度规则

| 等级 | 判定条件 | 界面 |
|---|---|---|
| 高 | ≥ 2 条强证据（同部件+同现象，或引用条款明确含数字）；无冲突 | 绿色「高」 |
| 中 | 1 条强证据，或仅有语义相似；或存在轻微冲突 | 黄色「中」 |
| 低 | 仅弱相关；或抽取字段缺失；或条款模糊 | 灰色「低」，默认折叠 |

### 7.2 强制人工确认的场景

- 引用被用于检验判定（M2 不合格判定）。
- 预警对象为个人（设计人员）。
- 归因结论涉及责任划分。
- 档案冲突且无变更单。
- 置信度为低。

### 7.3 反馈闭环

| 动作 | 落库 | 用途 |
|---|---|---|
| 👍 / 👎 | `ai_feedback` | 评测与回归 |
| 修正抽取字段 | 保存 AI 原值 + 人工值 | 计算字段准确率，优化词典/Prompt |
| 引用「有异议」 | `citation_review` | 触发知识修订 |
| 预警「误报」 | `alert.status=dismissed` | 规则调优样本 |

## 八、评测

### 8.1 数据集

| 集合 | 规模 | 构成 | 用途 |
|---|---|---|---|
| 抽取集 | 30 条 | 报修单文本 + 人工标注字段 | 字段 F1 |
| 相似集 | 40 对 | 人工标注「是否同类」 | Recall@5 / Precision |
| 问答集 | 20 条 | 11 台整机 × 6 类意图，含 4 条应拒答、3 条冲突 | 答案正确率、引用准确率 |
| 预警集 | 10 条 | 人工标注「应预警/不应预警」 | 预警准确率 |
| 回归集 | 50 条 | 历次修过的 badcase | 防止改一个坏一个 |

### 8.2 指标与通过线（Demo）

| 指标 | 通过线 |
|---|---|
| 要素抽取字段 F1 | ≥ 0.85 |
| 相似问题 Recall@5 | ≥ 0.80 |
| 问答答案正确率 | ≥ 0.90 |
| 引用准确率 | 1.00 |
| 应拒答场景正确拒答 | 1.00 |
| 预警准确率（人工复核） | ≥ 0.75 |

### 8.3 评测方法

- **人工标注为准**，模型自评不算数。
- 每次改 Prompt / 换模型 / 改词典 → 跑全量回归，记录版本对比。
- 线上用 👍/👎 与「有异议」持续采样，每周抽 20 条进回归集。

## 九、降级与容错

| 故障 | 降级策略 | 用户看到 |
|---|---|---|
| 大模型超时（>15s） | 返回结构化召回结果 + 规则排序，不做 AI 解读 | 「AI 解读暂不可用，以下为检索结果」 |
| 无 API Key | 全部走规则模板 + 预置答案 | 「演示模式：规则结果」 |
| 向量服务不可用 | 退化为关键词 + 结构化过滤 | 无感，质量略降 |
| 档案解析失败 | 该文档标「不可用」，答案中说明缺口 | 「某文档未成功解析，未纳入本次核对」 |
| JSON 校验失败 | 重试一次；再失败返回模板 | 「答案格式异常，请查看引用原文」 |
| 并发限流 | 排队 + 前端进度提示 | 「当前排队第 N 位」 |

### 9.1 Demo 缓存策略

演示现场网络不确定，对 8 条核心问答题预生成结果缓存：

- 命中的问题直接秒回缓存答案，同时后台可重新计算。
- 缓存带「演示缓存」标记，避免被误认为实时。
- 现场可一键切「实时模式 / 缓存模式」。

## 十、成本与性能预算（Demo 级）

| 项 | 预算 | 说明 |
