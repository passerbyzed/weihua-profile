# 04 技术协议库与引用溯源设计

> 所属：卫华产品质量智能平台（Demo）设计文档 ｜ 版本 v0.3 ｜ 2026-11-10
> 对应场景：M2 技术协议库（原「档案知识库」）。核心不是「能答」，而是「答得对、指得准、能核对」。

> **v0.3 调整**：`docs/*.pdf` 共同组成技术协议库，当前 3 份（55 / 74 / 63 页）。
> 用户先按编号/名称搜索并选中一份协议，再提问；回答只从选中协议中检索原文。
> `backend/data/build_agreements.py` 负责把 PDF 抽取为按页分块（当前 624 块），不做摘要或推导。
> 其中 `2001001111` 另有 12 条结构化条款，用于精确问答和不符合项核对；其余协议走原文检索。
> 第 1.2 节及后续的合同、图纸、变更单模型保留为后续多文件扩展参考。

## 一、目标与范围

### 1.1 要解决的问题

| 问题 | 现状 | 本设计的目标 |
|---|---|---|
| 要求散落 | 技术协议、图纸、变更单分属不同系统/人 | 按协议文件聚合，一次问清 |
| 版本混乱 | 协议改了、图纸没改；口头变更没落地 | 版本链 + 生效日期 + 冲突提示 |
| 答案不可信 | 问同事，得到的是记忆不是原文 | 每句结论挂原文，点开即定位 |
| 核对无留痕 | 电话确认，事后说不清 | 核对记录可查 |

### 1.2 档案范围与可信等级

| 档案类型 | 类型码 | 可信等级 | 主要用途 |
|---|---|---|---|
| 设计变更单（已生效） | `ECN` | A（最高，覆盖前序文档） | 变更后的最终要求 |
| 技术协议（最新生效版） | `TA` | A | 技术参数、材质、涂装、配套件、检验 |
| 合同（商务条款） | `HT` | A（商务）/ B（技术引用） | 质保、交期、罚则、验收 |
| 图纸（最新版） | `DWG` | B | 制造依据、图面标注、技术要求 |
| 检验标准 / 国标行标 | `STD` | B | 兜底判定依据 |
| 质量反馈函 | `FKL` | C | 历史问题，不作为要求依据 |
| 报价单 | `QT` | C | 申报标准参考 |
| 会议纪要 | `MIN` | C | 线索，必须人工确认后才可采信 |

> 等级不是绝对的：**同一事项上，生效的变更单 > 技术协议 > 图纸**；技术上冲突时按「更严者」提示并强制人工确认。

### 1.3 不在本期范围

- 扫描版图纸的自动 OCR 与尺寸识别（Demo 用预解析 JSON + 页面截图）。
- 三维模型、BOM 结构自动解析。
- 跨语言档案（英文合同）——后续版本。

## 二、档案接入

### 2.1 接入方式

| 方式 | 适用 | Demo |
|---|---|---|
| 文件上传（PDF/DOCX/图片） | 合同、协议、反馈函 | ✅ 手工上传 |
| PDM / 图纸系统同步 | 图纸、变更单 | 接口预留，Demo 用样例包 |
| 接口拉取 | 合同（SAP）、报价单 | 接口预留 |
| 邮件/共享目录监听 | 反馈函 | 后续 |

### 2.2 入库规则

1. **一档一记录**：同名不同版本分别入库，用 `supersedes` 串成版本链。
2. **归属必填**：技术协议库文件用 `library=agreement`；合同/图纸挂 `machine_id` 或 `contract_no`。
3. **哈希去重**：同文件重复上传提示「已存在」。
4. **解析状态可见**：待解析 / 解析中 / 待校对 / 可用 / 失败，失败给原因。
5. **原件不可变**：任何修订都产生新版本，不覆盖旧文件。

### 2.3 命名规范（建议）

```
{合同号}_{类型码}_{文档名}_{版本}.pdf
HT-2024-0316_TA_电动单梁起重机技术协议_v1.2.pdf
HT-2024-0316_DWG_总图_QD-2024-0316-01_v2.pdf
HT-2024-0316_ECN_面漆颜色变更_01.pdf
```

## 三、解析与切分

### 3.1 解析要求

| 要素 | 要求 | 用途 |
|---|---|---|
| 页码 | 与原文件严格一致 | 引用定位 |
| 坐标 | 段落/单元格 bbox | 原文高亮 |
| 章节层级 | 识别「第8章 / 8.1 / 8.1.2」 | 条款号、上下文 |
| 表格 | 保留行列结构，转成结构化表 | 参数表、配套件表 |
| 图面文字 | 图号、标注、技术要求文字块 | 图纸引用 |

### 3.2 切分策略（按档案类型）

| 档案 | 切分单元 | 说明 |
|---|---|---|
| 技术协议 | **按条款**（§x.y.z） | 一条一 chunk，保留上级章节标题做上下文前缀 |
| 合同 | 按条款/条目 | 商务条款、技术附件分开 |
| 图纸 | 按「标注块 / 技术要求条目 / 明细表行」 | 图面标注与标题栏分开 |
| 变更单 | 按「变更事由 / 变更内容 / 生效时间」 | 必须带生效日期 |
| 反馈函 | 按段落 | 用于问题检索，不做要求依据 |

**条款 chunk 示例**

| 字段 | 值 |
|---|---|
| `clause_id` | `CL-DOC-TA-LD5-2024-0316-01-8.1.2` |
| `clause_no` | `8.1.2` |
| `section_path` | `8 涂装、包装与运输 > 8.1 表面处理与涂层` |
| `text` | `涂层体系及干膜厚度见下表，总干膜厚度室内不低于 200 μm，室外不低于 240 μm。` |
| `page_no` | `6` |
| `clause_type` | `coating` |
| `bbox` | `[120, 640, 520, 690]` |

### 3.3 条款类型（`clause_type`）

`parameter` 参数 · `material` 材质 · `coating` 涂装 · `component` 配套件 · `inspection` 检验 · `standard` 标准引用 · `warranty` 质保 · `delivery` 交付 · `commercial` 商务 · `other`

类型用于检索时按问题意图过滤（问油漆就优先 `coating`）。

### 3.4 元数据（每个 chunk 必带）

| 字段 | 说明 |
|---|---|
| `machine_id` / `contract_no` | 归属整机 / 合同（技术协议库文件可空） |
| `library` | `agreement` 表示技术协议库文件 |
| `doc_type` / `doc_no` / `version` | 文档身份 |
| `effective_date` / `status` | 生效日期、是否生效 |
| `clause_no` / `section_path` | 条款定位 |
| `page_no` / `bbox` | 原文定位 |
| `clause_type` | 条款类型 |
| `components[]` | 涉及的部件（吊钩、钢板、涂装层…） |
| `normalized_values{}` | 抽出的结构化值（如 `{dft: 240, unit: "μm"}`） |
| `confidentiality` | 密级 |

> `normalized_values` 是非标判定的关键：只靠文本相似度判不出 240 与 200 的差别，必须结构化后与标准配置库比对。

## 四、检索设计

### 4.1 检索链路

```
问题
  → ① 意图与对象识别（问什么：非标核查 / 参数 / 标准 / 检验依据；对象：油漆/吊钩/钢板）
  → ② 范围锁定（技术协议文件 `2001001111技术协议 模拟数据`）
  → ③ 三路召回
        ├ 结构化过滤：doc_type ∈ {TA, DWG, ECN, HT}，clause_type ∈ 目标类型，status=生效
        ├ 关键词：FTS5/BM25（中文分词），命中「膜厚」「吊钩」「Q355B」等
        └ 向量：条款 embedding 与问题 embedding 相似度
  → ④ 融合排序（RRF，结构化命中加权）
  → ⑤ 重排（可选，LLM 判断条款是否真的回答问题）
  → ⑥ 覆盖度检查（油漆/吊钩/钢板三项是否都有命中？缺哪项补检）
  → ⑦ 进入答案组装
```

### 4.2 排序规则

| 信号 | 权重 | 说明 |
|---|---|---|
| 结构化命中（文档类型、条款类型、部件） | 0.35 | 强约束，不命中基本不相关 |
| 关键词 BM25 | 0.25 | 术语精确匹配（Q345B、Sa2.5、150μm） |
| 向量相似度 | 0.30 | 语义泛化（「漆膜厚度」↔「干膜厚度」） |
| 文档优先级（变更单 > 协议 > 图纸） | 0.10 | 同等相关时取更权威 |

最终召回 Top 8 条款进入答案组装，覆盖度检查不足时放宽到 Top 15。

### 4.3 覆盖度检查（避免「问了三个只答两个」）

对问题中识别出的每个对象（油漆、吊钩、钢板）单独检查是否有命中：

- 有命中 → 进入结论。
- 无命中 → 结论里明确写「未在档案中找到关于 X 的要求」，而不是省略。
- 若该对象在标准配置库有标准值，同时给出「标准配置值」，并注明「档案未提及专用要求」。

## 五、引用与溯源规范

### 5.1 引用格式（界面与导出统一）

```
[C1] 《LD5-2024-0316 电动单梁起重机技术协议》 v1.2
     §8.1.2 涂装、包装与运输 > 8.1 表面处理与涂层 · 第 6 页
     原文：“涂层体系及干膜厚度见下表，总干膜厚度不低于 240 μm（本项目室内环境亦按 240 μm 执行）。”
     档案编号：DOC-TA-LD5-2024-0316-01 ｜ 生效：2024-02-20 ｜ 状态：生效
     核对：待核对
```

### 5.2 引用粒度

- **最小到条款**，不引用整篇文档。
- 数字类结论（150μm、8mm、9、12 个月）必须逐字出现在引用原文中。
- 图纸引用必须带图号 + 版本 + 区域（图面标注 / 技术要求第 N 条 / 明细表第 N 行）。
- 变更单引用必须带生效日期。

### 5.3 答案中的引用标记

- 正文用 `[C1]` 上标标记，鼠标悬浮显示原文摘要。
- 引用清单按出现顺序编号，不按文档排序。
- 同一结论多个来源时并列：`[C1][C4]`，并在冲突区说明两者差异。

### 5.4 核对状态

| 状态 | 含义 | 界面 |
|---|---|---|
| 待核对 | AI 生成，尚无人确认 | 灰色「待核对」 |
| 已确认 | 人工确认引用支撑结论 | 绿色「已核对 · 张工 · 11-10」 |
| 有异议 | 人工认为引用不支撑或原文有误 | 红色「有异议」，进入知识修订 |

## 七、冲突与版本处理

### 7.1 常见冲突类型

| 类型 | 例子 | 处理 |
|---|---|---|
| 协议 vs 图纸 | 协议 240μm，图纸 200μm | 并列展示；建议按更严者；强制技术确认 |
| 协议 vs 变更单 | 协议海灰色，变更单改橘红 | 采信生效变更单，并注明「已覆盖协议」 |
| 图纸版本 | 总图 v1 与 v2 板厚不同 | 只采信最新生效版；旧版仅作历史参考 |
| 协议版本 | v1.1 与 v1.2 | 只采信最新生效版；标明被替代 |
| 口头/会议纪要 vs 正式档案 | 会上说改，档案没改 | 纪要只作线索，提示「需正式变更」 |

### 7.2 采信优先级

```
生效变更单  >  最新生效技术协议  >  最新版图纸  >  合同技术附件  >  国标/行标  >  会议纪要/报价单
```

补充规则：

1. 商务条款（质保、交期、罚则）以合同为准。
2. 技术条款冲突且无变更单时，按「更严者」提示，且必须人工确认。
3. 任何采信决定都要在答案里写明理由和依据，不能静默选择。

### 7.3 版本链

- 每份文档记录 `supersedes`，形成链：`v1.0 → v1.1 → v1.2`。
- 检索默认只检索「生效」版本；用户可切换「包含历史版本」查看演变。
- 变更单挂到它影响的文档上，答案里同时展示「原要求 → 变更后」。

## 八、防幻觉设计（本模块的底线）

| 机制 | 做法 |
|---|---|
| **只答检索到的** | 答案中的每一项要求必须来自召回条款，禁止模型凭常识补全 |
| **数字逐字校验** | 提取答案中的数字+单位，在引用原文中做子串匹配；不匹配则该结论降级或删除 |
| **引用 grounding** | 每条结论至少 1 条引用；引用必须属于本次召回集合；否则结论无效 |
| **无依据就说没有** | 统一话术「未在已入库档案中找到关于 X 的要求」+ 给出标准配置值作参考 |
| **区分原文与归纳** | 引用块是原文（带引号），结论是归纳（AI 标识），视觉上分开 |
| **冲突不隐藏** | 检测到多文档不一致必须展示，不允许「选一个看起来对的」 |
| **不确定要明说** | 模糊条款标 `vague`，写「描述模糊，无法量化核对」 |
| **禁止推断意图** | 不猜测「客户其实想要什么」，只回答档案写了什么 |

### 8.1 拒答与降级话术

| 场景 | 话术 |
|---|---|
| 档案未入库 | 「该整机尚未上传技术协议/图纸，无法核对。已找到同类机型标准配置，仅供参考。」 |
| 检索无命中 | 「未在档案中找到与『XX』相关的要求。」 |
| 条款模糊 | 「协议仅写『按需方要求』，未给出具体数值，无法判定，建议书面确认。」 |
| 版本冲突 | 「检测到两处不一致，已并列展示，请确认以哪份为准。」 |
| 模型超时 | 「已检索到以下条款，AI 解读暂不可用，请直接查看原文。」 |

## 九、权限与密级

| 密级 | 可见角色 | 处理 |
|---|---|---|
| 公开 | 全部 | 正常 |
| 内部 | 质量、技术、检验、售后 | 正常，水印 |
| 机密（合同金额、客户敏感条款） | 质量经理及以上 | 结论可见，金额字段脱敏 |

- 客户隔离：默认只能看自己负责客户/整机的档案，跨客户检索需授权。
- 引用导出：导出 PDF 时自动带「文档编号 + 页码 + 导出人 + 时间」。

## 十、核对闭环与知识维护

```
AI 答案 → 人工核对（确认 / 有异议）
              │
              ├─ 确认 → citation_review 记录「已核对」，答案可用于检验判定
              └─ 有异议 → 填写原因（原文错 / 引用错 / 结论错 / 档案缺失）
                            → 生成「知识修订」工单
                            → 修订档案或补充条款 / 调整切分 / 调整 Prompt
                            → 重跑该问题，比对结果
```

维护动作：

| 触发 | 动作 |
|---|---|
| 用户点「有异议」 | 进修订队列，48 小时内处理 |
| 新版本档案入库 | 自动失效旧版引用，提示「依据已更新」 |
| 条款切分错误 | 人工调整切分点，重建索引 |
| 高频未命中问题 | 补充档案或词典（如「漆膜」同义词） |
