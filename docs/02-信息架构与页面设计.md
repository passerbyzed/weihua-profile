### 2.1 整机上下文

- 顶部不再放全局整机选择器（已移除），避免所有页面被一台设备绑架。
- 整机选择放在真正需要的地方：
  - M2 智能问答：问句上方选整机；
  - M2 不符合项核对：表单第一项选整机；
  - M1：整机来自报修单本身，列表可按关键字搜产品编号；
  - M3：规则按问题特征计算，不依赖当前整机。
- 问答页切换整机会清空上一台的答案。

### 2.2 演示模式标识

右上角「演示环境 · 数据为构造数据」常驻；左侧栏也有「演示数据」标记，避免被误读为真实结论。

## 三、四条核心流程

### F1 新售后问题研判（M1 主线）

**触发**：售后服务平台同步一条新报修单，或在 M1-02 报修单列表里点开一条。

| 步骤 | 页面 | 用户动作 | 系统行为 | 输出 |
|---|---|---|---|---|
| 1 | M1-02 | 按售后状态/定责/来源/故障类型筛选，或搜索报修单号 | 列表分页展示 100 条报修单 | 目标报修单 |
| 2 | M1-03 | 点开报修单 | ①展示报修与质量事实 ②四轴召回 ③质量链补全 ④处置建议 | 研判面板 |
| 3 | M1-03 | 看相似历史、质量链、建议 | 每条证据可展开、可跳原始单据 | 质量链视图 |
| 4 | M1-03 | 确认/修正归因，采纳建议 | 记录人工确认，保存 AI 原版 | 已确认研判 |
| 5 | M1-03 | 点「生成分析报告」 | 生成可复制的分析报告草稿 | 报告文本 |

**异常分支**

- 产品编号识别失败 → 提示「未匹配到整机」，允许手工指定或先按客户+机型检索。
- 召回到 0 条 → 明确显示「未找到历史同类问题」，仍给出质量链和排查建议，不编造历史。
- 大模型超时 → 先出结构化召回结果（按规则排序），AI 解读后补。

### F2 协议问答（M2 主线）

**触发**：检验员/技术/报价在 M2-01 提问，或从 M1 问题详情点「查技术协议要求」跳转。

| 步骤 | 页面 | 用户动作 | 系统行为 | 输出 |
|---|---|---|---|---|
| 1 | M2-01 | 搜索编号/名称，选中一份协议，再输入问题 | 只在该协议内检索原文，锁定文件范围 | 加载态 |
| 2 | M2-01 | 等待 3～10 秒 | 检索条款 → 组装逐项要求 → 标注页码 → 引用 grounding 校验 | 结构化答案卡 |
| 3 | M2-01 | 逐项看要求、点引用 | 打开 M2-04，定位页码并高亮原文 | 原文核对 |
| 4 | M2-01 | 点「确认无误」或「有异议」 | 写引用核对记录（M2-05） | 核对留痕 |
| 5 | M2-01 | 点「生成核对单」 | 导出逐项清单（可打印/给检验） | 核对单 |

**异常分支**

- 协议未提及某对象 → 明确显示「协议中未找到」，不编造。
- 大模型不可用/数字校验不通过 → 回退规则结论并提示。
- 条款无法支撑结论 → 该条降级为「未找到依据」，不参与结论。

### F3 不符合项核对（M2 专项）

**触发**：检验过程中发现实测值不符合，检验员在 M2-02 录入不符合项。

| 步骤 | 页面 | 用户动作 | 系统行为 | 输出 |
|---|---|---|---|---|
| 1 | M2-02 | 选检查项（涂层膜厚/板厚…）+ 填实测值 | 带出协议要求值、条款号和页码 | 对照初稿 |
| 2 | M2-02 | 点「开始核对」 | 规则比对：实测值与协议要求 | 判定结论 |
| 3 | M2-02 | 查看依据 | 显示协议原文和页码 | 核对依据 |
| 4 | M2-02 | 生成核对记录 | 形成检验留痕 | 记录 |

**判定口径**：

1. 实测值 ≥ 协议要求 → 符合协议要求。
2. 实测值 < 协议要求 → 不符合协议要求，给出返工/让步接收/同批核查建议。
3. 协议未规定 → 不做合格判定，提示补充依据。

### F4 预警发现与处置（M3 主线）

**触发**：每日定时计算 + 新问题入库时实时增量计算。

| 步骤 | 页面 | 用户动作 | 系统行为 | 输出 |
|---|---|---|---|---|
| 1 | M3-03 | 看预警列表 | 按等级/对象/时间排序，显示模式摘要与证据数 | 预警卡片 |
| 2 | M3-03 | 点开预警 | 展示规则条件、阈值、窗口、证据问题、涉及整机/客户、建议动作 | 预警详情 |
| 3 | M3-03 | 确认 / 标为误报 / 转整改 | 状态流转，记录处理人与理由 | 状态更新 |
| 4 | M3-03 | 填整改任务（负责人、期限） | 生成任务，进入跟踪 | 整改任务 |
| 5 | M3-03 | 到期验证 | 对比整改前后同类问题数 | 关闭 / 重开 |

**异常分支**：样本不足（对象相关问题 < 3 起）→ 不出统计预警，只在驾驶舱显示「提示级线索」。

### 4.3 M1-03 问题详情 + 质量链（Demo 最重要的页面）

左右分栏：左侧「问题事实」，右侧「AI 研判」。质量链横跨底部或用时间轴。

```
┌ 问题 QI-202611-0032 · 河南华丰 · LD5-2024-0316 · 运行异响 ─────────────┐
│ 状态：研判中   来源：售后服务平台   发现：2026-11-08   质保内           │
├──────────────────────────────┬───────────────────────────────────────┤
│ 【问题事实】                  │ 【AI 研判】 置信度 中   [重新研判]      │
│ 客户：河南华丰食品有限公司     │ ① 相似历史（4 条）                     │
│ 整机：LD5-2024-0316          │  ┌ 2024-09 同客户同部件 轴承座同轴度 92% │
│ 机型：LD5-10.5 A5            │  │ 处置：更换轴承座+复测  归因：制作问题  │
│ 部件：起升机构/卷筒/轴承座     │  └ 2025-03 同部件 卷筒异响 81%          │
│ 现象：起升时左侧异响，重载明显  │ ② 质量链（7 段，完整度 5/7）           │
│ 描述：……（原文）              │ ③ 根因假设（2 条，带证据）             │
│ 附件：录音 1 条、照片 2 张     │ ④ 处置建议（按历史有效性排序）          │
│                              │ ⑤ 断点提示：无该批次装配检验记录        │
└──────────────────────────────┴───────────────────────────────────────┘
```

**质量链时间轴**（底部通栏）：

```
需求/合同 ── 设计 ── 来料 ── 制造 ── 检验 ── 交付 ── 售后
   ✓          ✓       ✓      ✓       ✗       ✓      ●
 协议§4.1   图纸v2  炉批号   装配二班  缺记录  2024-05  本次
```

- 每段可点开看证据；✗ 表示证据缺失（断点），是重要输出，不是错误。
- 断点会进入 M3 的「追溯完整性」统计。

**AI 研判面板的输出约束**：

- 每条历史问题必须显示「命中原因标签」：同客户 / 同机型 / 同部件 / 现象相似 92%。
- 每个根因假设必须挂证据，证据不足的假设标注「待验证」。
- 建议措施显示历史采用次数与是否解决（有效 / 无效 / 未知）。

### 4.3.1 M1-05 问题库问答与报表导出

```
┌ 问题库智能问答 ─────────────────────────────────────────────────────┐
│ 问：缓冲器和制动器各出现多少次？                                    │
│ [提问] [生成报表]                                                   │
├─────────────────────────────────────────────────────────────────────┤
│ 报表格式： (●) Excel  ( ) PDF  ( ) Word                             │
│ 统计：缓冲器 12 条（12.0%） / 制动器 5 条（5.0%）                   │
│ 每个维度：柱状图（月度趋势）+ 饼图（原因归属）+ 汇总表           │
└─────────────────────────────────────────────────────────────────────┘
```

要点：
- 「生成报表」按钮在「提问」旁边；先填写问题，再选格式。
- 维度从问题里识别：问题部件（缓冲器、制动器…）、故障类型、原因归属、客户、整机、问题现象；同时命中多个维度时分别统计，不合并、不丢维度。
- 时间词（最近三个月 / 本月 / 今年）会作为统计范围。
- Excel：概览 + 每个维度一个 sheet（柱状图 + 饼图 + 汇总表）；PDF/Word：概览 + 分维度图表和汇总表，均可在浏览器直接下载。
- 不输出高频部件 Top 10，也不输出逐条问题明细。

- 结论先行，逐项要求跟上，引用垫底——符合「先给答案，再给依据」的核对习惯。
- 引用卡必须含：文件名称 + 版本 + 条款号 + 页码 + 原文 + 「查看原文」。
- 不再按整机查询，页面只针对协议文件本身。

### 4.5 M2-02 不符合项核对

对照协议条款是核心：

```
┌ 不符合项核对 ───────────────────────────────────────────────────────┐
│ 技术协议：2001001111 │ 检查项：箱梁内部漆膜总厚度 │ 实测：140 μm │ 协议要求：≥150 μm      │
├──────────────┬──────────────┬──────────────────────────────────────┤
│ 协议要求      │ 实测值        │ 判定                                  │
│ ≥150 μm      │ 140 μm       │ 不符合协议要求                        │
│ §5 第44页     │ 检验记录      │ 建议：返工/让步接收/同批核查          │
├──────────────┴──────────────┴──────────────────────────────────────┤
│ 判定依据：协议原文「漆膜干燥总厚度≥150μm」（§5，第44页）             │
│ 协议原文：……                                                        │
└──────────────────────────────────────────────────────────────────────┘
```

要点：判定由规则计算，不依赖模型；结论必须同时给出协议要求值、实测值、条款和页码。

## 五、全局交互约定

| 约定 | 说明 |
|---|---|
| **AI 标识** | 所有 AI 生成内容带浅紫底 + 「AI」角标；人工修改后角标变为「AI·已修订」 |
| **证据卡** | 统一组件：标题 + 来源单据/文档 + 时间 + 相关片段 + 「查看」按钮 |
| **置信度** | 高/中/低三档 + 悬浮说明（依据条数、是否有冲突）；低置信结论默认折叠 |
| **无依据** | 统一用「未找到依据」灰卡，禁止用推测填空 |
| **加载态** | 分步提示：解析问题 → 检索档案 → 比对标准 → 生成结论；超过 8 秒显示「可先看已检索到的条款」 |
| **空态** | 给出下一步动作（如「上传技术协议」「先选整机」），不出现空白页 |
| **错误** | 区分「数据缺失」「检索失败」「模型超时」，各自给不同按钮 |
| **反馈** | 每条 AI 结论右下角 👍/👎 + 一句话原因，落库用于评测 |
| **核对留痕** | 确认/异议都必须记录人、时间、意见，M2-05、M3-03 可查 |
| **复制** | 结论可一键复制为纯文本（带引用编号），便于贴到反馈函/邮件 |
