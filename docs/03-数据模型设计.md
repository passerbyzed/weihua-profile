# 03 数据模型设计

> 所属：卫华产品质量智能平台（Demo）设计文档 ｜ 版本 v0.1 ｜ 2026-11-10
> 目标：定义「一机一档」的数据骨架，让 M1/M2/M3 共用同一套实体和字典。

---

## 一、设计原则

| 原则 | 说明 |
|---|---|
| **一机一档** | 所有业务事实必须能挂到 `machine_id`（整机产品编号）；挂不上的进「待归档池」 |
| **三层分离** | 原始记录（不可变）→ 结构化事实（可人工修正）→ AI 结论（可重算），三层分开存，互不覆盖 |
| **字典先行** | 部件、故障现象、原因分类先归一，再谈检索和统计，否则「吊钩/钩头」永远对不上 |
| **来源可溯** | 每条事实记录 `source_system`、`source_no`、`source_hash`、`synced_at` |
| **软删除 + 版本** | 业务数据不做物理删除；档案走版本链，旧版本保留可查 |
| **枚举稳定** | 状态、类型、等级用固定枚举，不用自由文本 |

## 二、实体清单

### 2.1 主数据

| 实体 | 表名 | 说明 | 关键字段 |
|---|---|---|---|
| 客户 | `customer` | 使用单位，支持集团/子公司归并 | `id, name, alias, parent_id, region, industry` |
| 合同 | `contract` | 商务合同/项目 | `contract_no, customer_id, signed_date, delivery_date, amount` |
| 机型 | `machine_model` | 型号规格族 | `id, model_code, category, spec_pattern, work_level` |
| 整机 | `machine` | 单台设备，质量数据主键 | `id, product_no, contract_no, model_id, serial_no, manufacture_date, warranty_end, usage_unit` |
| 部件 | `component` | 归一后的标准部件 | `id, code, name, parent_id, category, is_standard` |
| 班组 | `team` | 制作/涂装/装配/焊接班组 | `id, name, workshop, process` |
| 人员 | `staff` | 设计、检验、售后、班组长 | `id, name, employee_no, role, dept` |
| 供应商 | `supplier` | 外协/外购厂家 | `id, name, category, qualification` |

### 2.2 事实数据

| 实体 | 表名 | 说明 | 关键字段 |
|---|---|---|---|
| 质量问题 | `quality_issue` | 统一的问题单（售后/检验/反馈函/客诉） | 见 3.1 |
| 检验记录 | `inspection_record` | 来料/过程/出厂检验 | `machine_id, stage, item_id, standard_value, measured_value, result, inspector_id, inspected_at, batch_no` |
| 追溯记录 | `trace_record` | 部件—批次—班组—工序 | `machine_id, component_id, batch_no, heat_no, supplier_id, team_id, process, operator, record_date` |
| 整改任务 | `action_task` | 由问题或预警发起 | `id, source_type, source_id, owner_id, due_date, status, measure, verify_result` |
| 同步日志 | `sync_log` | 记录每次数据接入 | `id, source_system, started_at, fetched, inserted, updated, failed, message` |

### 2.3 档案数据

| 实体 | 表名 | 说明 | 关键字段 |
|---|---|---|---|
| 档案文档 | `quality_document` | 合同/技术协议/图纸/变更单等 | 见 3.3 |
| 条款 | `document_clause` | 可引用单元 | `id, document_id, clause_no, section_path, page_no, text, clause_type, bbox` |
| 标准配置 | `standard_config` | 机型标准值库 | `id, model_id, component_id, item_code, standard_value, unit, standard_ref` |
| 引用 | `citation` | AI 结论 → 条款 | `id, insight_id, clause_id, snippet, page_no, confidence, verify_status, verified_by` |
| 引用核对记录 | `citation_review` | 确认/异议留痕 | `id, citation_id, action, comment, reviewer_id, created_at` |

### 2.4 AI 数据

| 实体 | 表名 | 说明 | 关键字段 |
|---|---|---|---|
| AI 结论 | `ai_insight` | 一次研判/问答/归因的结构化输出 | `id, insight_type, target_type, target_id, input_json, output_json, evidence_json, confidence, model, prompt_version, is_confirmed, created_at` |
| 预警 | `alert` | 高频问题预警 | 见 3.4 |
| 预警证据 | `alert_evidence` | 预警关联的问题 | `alert_id, issue_id, weight` |
| 反馈 | `ai_feedback` | 用户对 AI 结论的评价 | `insight_id, rating, reason, user_id` |

## 三、核心实体字段

| `report_time` | TEXT | | 报修时间 `HH:MM` |
| `after_sales_status` | TEXT | ✓ | 待派工 / 已派工-待完工 / 已完工-待评价 / 已完工-已评价 / 已取消 |
| `responsibility_status` | TEXT | ✓ | 未开始 / 待定 / 有责 / 无责 |

| `entry_method` | TEXT | ✓ | 订单 / 手工 / 导入 |

| `contact_name` / `contact_phone` | TEXT | | 使用单位联系人、电话 |

| `source_hash` | TEXT | | 内容哈希，用于幂等去重 |
| `machine_id` | TEXT | | 整机产品编号；未匹配时为空，进待归档池 |
| `contract_no` | TEXT | | 合同号（冗余，便于按合同统计） |

| `severity` | TEXT | ✓ | 一般 / 较重 / 严重 / 重大 |

| `supplier_id` | INTEGER | | 相关供应商 |

| `resolved` | INTEGER | | 0/1 |
| `closed_at` | DATETIME | | 关闭时间 |
| `recurrence_of` | INTEGER | | 如果是复发，指向原问题 `id` |
| `status` | TEXT | ✓ | 质量状态，见 4.1 状态机（研判中 / 整改中 / 已关闭） |

## 四、状态机

### 4.1 质量问题

```
待归档 ──匹配整机──→ 新发现 ──→ 研判中 ──→ 已归因 ──→ 整改中 ──→ 验证中 ──→ 已关闭
   │                    │           │                      │
   └──手工指定整机──→    └──判为无效/重复──→ 已合并        └──验证不通过──→ 整改中
                                                            已关闭 ──12个月内再发──→ 新发现（recurrence_of 指向原问题）
```

### 4.2 预警

```
待确认 ──确认──→ 已确认 ──建任务──→ 整改中 ──验证有效──→ 已关闭
   │                                    
   ├──误报──→ 已关闭（标记误报，回写规则样本）
   └──样本不足──→ 提示级（不进预警列表，只在驾驶舱展示）
```

### 4.3 档案

```
上传 → 解析中 → 待校对 → 生效 → 已替代 → 作废
                 │
                 └──解析失败──→ 待人工处理
```

### 4.4 引用核对

```
待核对 ──确认无误──→ 已确认
   └──有异议──→ 有异议 ──知识修订──→ 重新生成引用
```

## 五、编码规则

| 对象 | 规则 | 示例 |
|---|---|---|
| 质量问题 | `QI-{YYYYMM}-{4位序号}` | `QI-202611-0032` |
| 预警 | `QA-{YYYYMM}-{4位序号}` | `QA-202611-0007` |
| 引用 | `C{序号}`（答案内） + `CT-{insight_id}-{序号}`（库内） | `C1` / `CT-1024-1` |
| 档案 | `DOC-{类型码}-{归属}-{序号}` | `DOC-TA-LD5-2024-0316-01` |
| 条款 | `CL-{document_id}-{clause_no}` | `CL-DOC-TA-LD5-2024-0316-01-8.1.2` |
| 整机 | 直接使用产品编号 | `LD5-2024-0316` |
| 机型 | 型号编码 | `LD5`、`CD1`、`MH`、`QD`、`BZ` |
| 部件 | `C-{大类}-{中类}-{序号}` | `C-01-03-002` |

类型码：`HT` 合同、`TA` 技术协议、`DWG` 图纸、`ECN` 变更单、`STD` 检验标准、`FKL` 反馈函、`QT` 报价单、`MIN` 会议纪要。

## 六、ER 关系

```
customer 1 ─── N contract 1 ─── N machine N ─── 1 machine_model
                                   │  │
                                   │  └── N inspection_record
                                   │  └── N trace_record ── N component / team / supplier
                                   │
                                   └── N quality_issue N ─── 1 component
                                            │  │
                                            │  └── 1 staff（designer）/ team / supplier
                                            │
                                            └── N alert_evidence ── N alert ── N action_task

quality_document 1 ─── N document_clause 1 ─── N citation N ─── 1 ai_insight
        │                                              │
        └── N standard_config                         └── N citation_review
```

说明：

- `quality_issue.recurrence_of` 自关联，形成「复发链」。
- `machine` 的 `product_no` 就是售后系统的产品编号，保证两套系统能对上。
- `standard_config` 按「机型 + 部件 + 项」存标准值，是非标判定的基准。

### 7.2 故障现象分类（两级）

| 大类 | 现象（示例） |
|---|---|
| 机械 | 异响、振动、温升过高、漏油、卡滞、断裂、变形、磨损、松动、啃轨、跑偏 |
| 电气 | 无法启动、跳闸、失电、限位失效、变频故障、控制失灵、绝缘不良 |
| 结构 | 焊缝裂纹、母材开裂、变形、螺栓松动 |
| 涂装 | 起泡、脱落、色差、膜厚不足、流挂、锈蚀 |
| 安全 | 超载、溜钩、制动失效、防碰撞失效 |
| 其他 | 文件缺失、标识错误、包装破损 |

### 7.3 原因分类与售后字典映射

| 售后「故障原因归属」 | 归一责任类型 | 5M1E 归属 | 典型二级根因 |
|---|---|---|---|
| 设计问题 | 设计 | 法 | 图纸标注缺失、选型不当、公差标注错误、协议未传递到设计 |
| 制作问题 | 制作 | 人 / 法 | 下料偏差、焊接缺陷、同轴度超差、装配间隙、涂装前处理 |
| 外协问题 | 外协 | 料 | 外协件材质不符、尺寸超差、热处理不合格 |
| 来料（新增） | 来料 | 料 | 钢板分层、材质证明缺失、炉批号不符 |
| 发货问题 | 运输 | 环 | 包装不当、运输磕碰、防锈失效 |
| 客户（质保内/外） | 使用 | 人 / 环 | 超载、斜拉斜吊、维保缺失、环境腐蚀 |
| 技术支持 | 服务 | 人 | 指导错误、响应不及时 |
| 公司自营 | 安装 | 法 | 安装精度、调试不到位 |
| 其他 | 其他 | — | 待归因 |

> 原字典必须原样保留（`attribution_raw`），映射表可配置，不改源系统口径。

### 7.4 非标判定枚举（M2 用）

| 枚举 | 含义 | 界面颜色 |
|---|---|---|
| `standard` | 与标准配置一致 | 灰 |
| `non_standard` | 与标准配置不同（高于或指定） | 橙 |
| `vague` | 描述模糊，无法量化核对 | 黄 |
| `non_compliant` | 低于标准/不满足强制要求 | 红 |
| `deviable` | 可偏离，需走变更 | 蓝 |

## 八、数据质量规则

| 规则 | 处理 |
|---|---|
| 产品编号格式校验 | 大写、去空格；不符合格式进待归档池并提示 |
| 源单号唯一 | 同系统同单号只入库一次；内容变化则更新并留版本 |
| 部件必填 | 缺失时先按现象推断，推断不出标「待补」，不阻塞入库 |
| 时间合理性 | 发现时间不得早于出厂日期；异常标记待核 |
| 复发判定 | 同整机 + 同部件 + 同现象，12 个月内 → 自动关联 `recurrence_of` |
| 归档完整性 | 整机无合同/无档案 → 质量链显示断点，进「追溯完整性」统计 |

## 十、表关系落地建议（给后端）

- 主键：主数据用自增整数，业务单据用「编号」做业务主键 + 自增 ID 双键。
- JSON 字段（`evidence_json`、`metric_json`、`output_json`）在 Demo 阶段直接存文本，SQLite 足够；试点换 PostgreSQL 时改 `JSONB`。
- 全文检索：Demo 用 SQLite FTS5 建 `document_clause.text` 与 `quality_issue.phenomenon` 的虚拟表。
- 向量：条款与现象各建一个向量表（`clause_vec`、`issue_vec`），Demo 数据量小，可直接内存加载。
- 所有「AI 生成」字段与「人工确认」字段分开，避免重跑覆盖人工结论。
