## 一、一句话定义

把散落在合同、技术协议、图纸、检验记录、质量反馈函、售后报修单里的质量信息，按「一机一档」串成一条可追溯的质量链，再用三个 AI 入口把它变成**可检索、可问答、可预警**的能力。

- **可检索**：售后问题质量库按「报修单」形式列出 100 条记录，可按报修单号、使用单位、联系人、售后状态、定责状态、来源、故障类型筛选；点进任意一条可看同客户/同机型/同部件的历史同类问题、当时怎么处理、最后归因是什么。
- **可问答**：先在技术协议库搜索并选中一份 PDF 协议，再问「对油漆、吊钩、钢板有什么要求」；只返回该协议原文，并把出处标到「文件 + 页码」；不做归纳、推算或补全。
- **可导出**：在问题库智能问答里按提问维度生成统计报表，支持 Excel / PDF / Word；报表含柱状图（月度趋势）和饼图（原因归属），不输出问题明细。问「缓冲器和制动器」，两个维度都会分别统计并成图。
- **可预警**：按「故障类型 + 原因归属 + 厂家 + 问题部件 + 备注关键词」配置规则，某类问题在时间窗口内达到次数阈值就预警，规则可在页面里改。

## 二、三个问题与三个模块

| # | 场景原话（节选） | 对应模块 | 一句话能力 | 主要用户 |
|---|---|---|---|---|
| 1 | 售后反馈一个新问题时，AI 自动检索历史档案，识别「同一客户 / 同一机型 / 同一部件，过去是否出过同类型问题」以及当时的处置方式、原因，形成完整的质量链条 | **M1 售后问题质量库** | 报修单列表 + 相似历史问题召回 + 质量链补全 + 处置建议 + 问题库问答 + 统计报表导出 | 售后工程师、质量工程师 |
| 2 | 在技术协议库搜索并选中一份 PDF 协议，问「对油漆、吊钩、钢板有什么要求」，系统只返回该协议原文，并标注页码供人核对 | **M2 技术协议库** | 协议搜索/选择 + 原文检索 + 页码引用 | 检验员、技术/设计、报价、质量工程师 |
| 3 | AI 从历史质量数据中发现规律，预警班组、设计人员高频发生的问题 | **M3 质量归因预警** | 条件规则 + 时间窗口 + 次数阈值 + 预警处置闭环 | 质量经理、质量工程师、部门主管 |
| 4 | 对已上线的质量优化、质量问题反馈、售后服务平台、质量追溯平台接入 AI 自动化数据分析，让数据驱动质量改善和趋势分析 | **数据底座 + M3 驾驶舱** | 跨系统数据接入与统一口径 | 质量部、管理层 |

> 三块不是三个孤立工具：M1 的每一次研判、M2 的每一次核对、M3 的每一条预警，都落在同一台「整机」、同一套「部件 / 故障 / 原因」字典上，互相喂数据。

## 三、产品结构一览

```
产品质量智能平台（质量智脑）
├── 0. 工作台 ........................ 今日待办、质量态势、快捷提问
├── 1. 售后问题质量库（M1）
│   ├── 报修单列表（筛选 / 分页 / 详情入口）
│   ├── 问题详情（AI 研判 / 质量链）
│   ├── 问题库问答（DeepSeek 汇总全部问题）
│   └── 相似问题检索（跨客户、机型、部件）
├── 2. 技术协议库（M2）
│   ├── 协议搜索/选择（docs 下 PDF 自动索引）
│   ├── 不符合项核对（协议要求 / 实测 / 判定）
│   ├── 档案浏览（按整机 / 合同）
│   ├── 原文查看器（引用定位 + 高亮）
│   └── 引用核对记录
├── 3. 质量归因预警（M3）
│   ├── 质量驾驶舱（趋势 / 分布 / TOP）
│   ├── 归因分析（班组 / 设计人 / 供应商 / 机型下钻）
│   ├── 预警中心（按规则实时计算）
│   ├── 预警配置（故障类型 / 原因归属 / 厂家 / 部件 / 备注 / 窗口 / 阈值）
│   └── 质量分析报告
└── 4. 数据与配置
    ├── 数据源接入状态
    ├── 知识库文档管理
    ├── 主数据与字典（部件归一、故障分类、原因分类、标准配置库）
    └── 演示数据与重置
```

三个模块共享一个「当前整机上下文」：在顶部选定产品编号（如 `LD5-2024-0316`）后，问题研判、档案问答、归因分析都默认围绕这台设备展开。

## 五、与现有系统的关系

本系统**不替代**任何已上线系统，定位是「跨系统的 AI 分析层 + 统一的整机质量档案」。

| 现有系统 | 本系统取什么 | 本系统回写什么 | 关系 |
|---|---|---|---|
| 售后服务平台（`weihua_shouhou`） | 报修单、产品编号、故障类型/原因归属/问题部件、问题描述、处理方法、录音转写 | 相似历史问题提示、AI 研判结论 | 数据源 + 能力增强 |
| 质量问题反馈（反馈函） | 反馈函正文、客户、产品、时间、处理结果 | 结构化标签、关联问题、复发标记 | 数据源 |
| 质量优化 | 整改单、整改措施、验证结果、费用 | 归因结论、同类问题合并建议 | 双向 |
| 质量追溯平台 | 班组、工序、炉批号、铭牌、检验记录、供应商 | 追溯断点提示、异常聚集预警 | 数据源 |
| OA | 审批流、任务、通知 | 整改任务、核对记录、分析报告 | 待办互通 |
| SAP | 合同号、物料/BOM、供应商、成本 | 无（只读） | 主数据 |
| 图纸 / PDM、文件服务器 | 图纸、技术协议、合同、变更单 | 无（只读） | 档案源 |

## 六、Demo 边界（明确不做什么）

| 不做 | 原因 | Demo 里的替代 |
|---|---|---|
| 打通真实 OA / SAP / PDM 接口 | 无接口文档、无测试环境 | 适配器接口 + 本地样例数据包，界面标注「演示数据」 |
| 全量 PDF/扫描件自动解析 | 两天内不稳定，扫描图纸 OCR 风险高 | 内置「预解析档案包」（JSON + 页面截图 + 条款坐标），解析链路保留接口 |
| 训练专属模型 | 数据量不足、周期不允许 | 复用通用大模型 + 结构化检索 + 规则校验 |
| 做登录、权限、审计 | 演示阶段不需要 | 单角色进入，权限矩阵只写设计 |
| 自动下结论、自动派工 | 质量责任判定必须人工确认 | 所有 AI 结论都是「建议」，带置信度与证据，需人工确认后生效 |
